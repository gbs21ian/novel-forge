# Novel Forge v1.2.1 — 개인 배포용 앱 내 업데이트

> **중요:** v1.2.1은 Obsidian의 공식 커뮤니티 플러그인 디렉터리용이 아닙니다. Obsidian 공식 개발자 정책은 자체 설치/자체 업데이트를 금지합니다. 이 기능은 사용자가 직접 설치한 개인 배포용 플러그인에서만 사용하세요. 공식 등록을 하려면 자체 업데이트 기능을 제거하고 Obsidian 또는 BRAT 업데이트를 이용해야 합니다.

**v1.2.0의 기능은 유지**: Gemini Context Caching, 요약/대화 슬라이딩 윈도우, 로컬 근거 검색, 문체 프로필, 다단계 AI 집필, 원고 백업/복원, 설정 근거 표시. v1.2.1에는 GitHub Releases 수동 업데이트 기능과 선택적 시작 시 알림을 추가했습니다.

## 1회 설치

1. `Novel-Forge-Obsidian-v1.2.1-Install.zip`을 압축 해제합니다.
2. `novel-forge` 폴더의 `main.js`, `manifest.json`, `styles.css`를 기존 `<보관함>/.obsidian/plugins/novel-forge/`에 덮어씁니다. **기존 `data.json`은 삭제하지 않습니다.**
3. Obsidian을 완전히 재시작하고 Novel Forge 플러그인을 켭니다.
4. Obsidian **설정 → Novel Forge → 플러그인 업데이트**에서 `GitHub 릴리스 저장소`를 `owner/repo` 형식으로 설정합니다. 아직 저장소가 없으면 아래 배포 방법부터 진행합니다.
5. **업데이트 확인**을 누릅니다. 현재보다 새 릴리스가 있을 때만 **확인한 버전 설치** 버튼이 활성화됩니다. 설치 후에는 Obsidian을 완전히 재시작하세요.

저장소가 비어 있으면 어떤 서버에서도 릴리스 파일을 다운로드하지 않습니다. 오픈소스 이름을 임의로 결정하거나 임의의 다른 사람의 GitHub 저장소로 연결하지 않았습니다.

## GitHub 배포 준비 (한 번만)

1. 본 소스 ZIP의 `novel-forge/` 폴더 내용 전체를 자신의 **공개 GitHub 저장소 루트**에 업로드합니다. 필요한 파일: `main.js`, `manifest.json`, `styles.css`, `build.js`, `src/`, `tests/`, `.github/workflows/release.yml` 등. `data.json`은 **업로드하지 않습니다.**
2. 처음 설정할 때 `v1.2.1` GitHub Release를 만듭니다. 반드시 `main.js`, `manifest.json`, `styles.css` 3개를 ZIP이 아닌 **개별 Release 자산**으로 첨부합니다. 웹 UI에서 태그 `v1.2.1`과 릴리스 제목을 만듭니다.
3. 다음부터는 GitHub에 코드를 올리고, `manifest.json`, `versions.json` 버전을 새 숫자로 올린 뒤, 예를 들어 아래 명령으로 태그를 푸시하면 GitHub Actions가 빌드/테스트/릴리스 자산 업로드까지 진행합니다.

```bash
git add .
git commit -m "Release v1.2.2"
git tag v1.2.2
git push origin HEAD
git push origin v1.2.2
```

주의: 실제 소스 변경 및 버전 갱신은 태그를 만들기 전에 끝내야 합니다. GitHub Actions가 동작하려면 저장소 Actions 사용이 가능하고 워크플로에 `contents: write` 권한이 필요합니다. 저장소의 기본 토큰 권한 또는 조직 정책에 따라 허용 설정이 필요할 수 있습니다. Github Release 자산의 `digest: sha256:...`가 조회 가능할 때만 플러그인 업데이트가 동작합니다.

## 보안/안전 동작

- 수동 업데이트 확인은 클릭할 때만 호출합니다. `시작 시 새 버전 알림` 옵션을 별도로 켜면 Obsidian을 시작할 때 **하루에 최대 1회** 공개 GitHub Release API를 조회합니다. **자동 설치는 하지 않습니다.**
- 다운로드 주소를 선택한 GitHub `owner/repo`의 HTTPS release 파일로 제한합니다. `main.js`, `manifest.json`, `styles.css` 세 자산만 수락하며 버전/크기/GitHub에서 제공하는 SHA-256 해시를 검사합니다.
- `manifest.json` 플러그인 ID 및 버전, 현재 앱 최소 버전, 다운그레이드 여부를 검증합니다. 위험하면 변경 없이 중단합니다.
- API 키가 포함된 `data.json`과 원고·메모·설정집은 업데이트하지 않습니다. GitHub 조회 요청에 API 키도 전송하지 않습니다.
- 원본 실행 파일은 `<설정폴더>/plugins/novel-forge/.novel-forge-updates/<버전-날짜>/`에 백업합니다. 다운로드 및 검사가 끝난 뒤에만 파일을 교체하며, 교체 중 예외가 발생하면 저장한 기존 파일을 복원합니다. 복원에도 문제가 생기면 오류 메시지의 백업 폴더에서 수동 복구하세요.
- GitHub Release 관리 권한이 있는 사람은 설치되는 코드를 바꿀 수 있습니다. **본인이 신뢰하는 저장소만 입력하세요.** SHA-256은 받은 데이터가 GitHub가 표시한 자산과 동일함을 검증하는 것이지, 배포자를 독립적으로 인증하는 전자서명은 아닙니다.
- 설치 후 재시작 전에는 실행 중인 기존 코드가 유지됩니다. 재시작 후 새 코드가 실행됩니다.

# Novel Forge v1.2.0 — Obsidian AI 웹소설 집필실

**Obsidian 보관함에서 작동하는 한국어 웹소설 집필 플러그인.** 모든 소설 원고·설정집은 평범한 Markdown 파일이며, AI 기능은 사용자가 입력한 외부 API 키(BYOK)로 호출됩니다. 공식 Obsidian 커뮤니티 플러그인 디렉터리에는 등록되어 있지 않습니다. 라이선스: MIT.

v1.2는 **AI 집필 특화형**으로, v1.1의 Gemini 서버 캐시·회차 요약·대화 슬라이딩 윈도우·자동 기억 압축을 유지하면서 로컬 검색(RAG), 단계별 AI 집필, 사용자 문체 분석, 원고 백업, 출처 표시를 추가한 버전입니다.

## 설치 / 1.1에서 업데이트

1. Obsidian **보관함 전체와 기존 `.obsidian/plugins/novel-forge/`를 백업**합니다.
2. 설정에서 Novel Forge 플러그인을 끄거나 Obsidian을 종료합니다.
3. `Novel-Forge-Obsidian-v1.2.0-Install.zip`을 풀고, 안의 **`novel-forge/` 폴더**를 보관함의 `.obsidian/plugins/` 안에 덮어씁니다.
4. 최종 파일 배치: `.obsidian/plugins/novel-forge/main.js`, `.obsidian/plugins/novel-forge/manifest.json`, `.obsidian/plugins/novel-forge/styles.css`.
5. **기존 `data.json`은 삭제하거나 덮어쓰지 마세요.** API 키·설정·기존 캐시 정보가 유지됩니다.
6. Obsidian을 재실행하고 설정 → 커뮤니티 플러그인 → Novel Forge 활성화 후, 새 v1.2 설정을 확인합니다.

**Obsidian 최소 버전 1.5.0.** 기존 작품의 회차/파일명은 바꾸지 않습니다. 신규 `05-기억/검색색인.json`, `03-자료/문체프로필.md`, `06-백업/` 폴더는 해당 기능 사용 시 자동 생성되거나 기존 작품에 직접 추가할 수 있습니다. **v1.2가 기존 작품에 자동으로 `문체프로필.md`를 덮어쓰지 않습니다.**

### 1. 로컬 검색(RAG) 활용

- 작품의 회차 원고(`02-회차/*.md`)와 기획·설정·집필 규칙 노트를 로컬에서 색인합니다. 외부 벡터 데이터베이스나 임베딩 API를 쓰지 않으며, 별도 크레딧도 필요 없습니다.
- 색인은 `05-기억/검색색인.json`에 **검색 토큰 빈도와 줄 범위**만 저장합니다. 원고 전체의 복제본을 JSON으로 만들지 않습니다. 원문이 변경되면 파일 수정 시각/길이 또는 콘텐츠 지문을 검사해 해당 항목을 갱신합니다.
- AI 집필 요청 때 추가 지시·선택 문장 또는 최근 원고 부분을 검색 질문으로 사용합니다. 관련도가 높은 조각을 기본 최대 **6개, 총 6,600자**까지 추출합니다. 검색 결과는 `[E1] 02-회차/0087-...md (17~22행)` 같은 출처 정보를 포함합니다.
- 검색 원문과 번호는 AI에 보내는 프롬프트에도 포함됩니다. **AI 검토가 `[E3]`을 인용했더라도 그 자체로 정답임을 보장하지 않습니다.** 플러그인은 없는 근거 번호를 경고하며, 검증이 필요한 경우 **원문 열기**로 직접 확인하세요.
- 한국어 음절쌍과 공백 기반의 **어휘 검색**으로, 동일한 이름/장소/사건 표현에 강하고 의미만 비슷한 동의어에는 약할 수 있습니다. 벡터 임베딩 검색, 모든 회차에 대한 완전한 추론, 자동 사실 판정까지 구현한 것은 아닙니다.
- 회차가 아주 길면 **첫 140,000자**까지 검색 색인에 포함됩니다. AI 프롬프트에 포함되는 발췌문 길이는 별도로 제한합니다.

### 2. AI 다단계 집필

1. 집필실 → **✦ 회차 초안** 또는 **✎ 이어쓰기**를 실행합니다.
2. 작품·회차·집필 지시를 선택한 뒤 **AI 다단계 집필** 체크박스를 켭니다. **기본적으로 체크 해제**되어 추가 API 비용이 갑자기 발생하지 않도록 했습니다.
3. 설정에서 활성화한 단계에 따라 장면 설계(기본 ON), 초고(항상), 검수(기본 ON), 최종 퇴고(기본 OFF)가 실행됩니다. 각 단계는 **별도 API 요청**이며 캐시·컨텍스트 비용이 발생할 수 있습니다.
4. 설계·검수·퇴고용 모델 ID는 설정에서 각각 입력합니다. **제공자는 동일**하고 해당 제공자에서 사용 가능한 모델이어야 합니다. 비우면 기본 집필 모델을 사용합니다.
5. 생성된 원고는 **미리보기로만 표시**하며, 결과 노트 저장·새 회차 저장·기존 회차 끝에 추가 중 하나를 **직접 선택**해야 반영됩니다.

**원고 보호:** AI 검수 결과는 정설을 직접 수정하지 않습니다. 퇴고 결과가 잘렸거나 너무 짧으면 원본 초고를 유지하고 부분 퇴고안만 저장합니다. 정상 퇴고가 적용될 때에도 원본 초고를 `04-AI결과/`에 별도로 저장합니다. 생성이 도중에 실패하면 확인 가능한 기존 생성 결과를 보존하지만, 완료되지 않은 단계의 결과가 자동으로 원고에 저장되지는 않습니다.

### 3. 문체 프로필

- 명령 팔레트 → `내 원고 문체 분석·프로필 만들기 (API 사용)` 또는 AI 집필 화면의 `문체 프로필 분석`을 실행합니다.
- 최신 5개 회차에서 발췌한 원고가 AI 제공자로 전송됩니다. 분석된 문장 길이, 시점, 대사, 문단 리듬, 묘사 방식 등의 **제안문을 먼저 확인**합니다.
- `문체 프로필로 승인·저장`을 클릭할 때만 `03-자료/문체프로필.md`에 반영합니다. 기존 프로필이 있으면 이전 내용을 `04-AI결과/`에 먼저 보관합니다.
- 문체프로필.md는 사용자가 **직접 수정**할 수 있습니다. 캐시를 사용할 때 내용 변경은 새 캐시가 필요할 수 있습니다.

### 4. 백업 / 복원

- 보관 위치: `06-백업/<회차 파일명>/<UTC 날짜-시간>-자동저장.md` 또는 `AI추가-이전.md`, `복원-이전.md`, `상태변경-이전.md`.
- 저장 이벤트 기준 **기본 10분에 최대 1개 스냅샷**, 회차별 **최근 12개 보존**(설정 변경 가능). 백업 **저장 성공 이후**에만 원본 변경을 허용하는 구간은 AI 추가·복원·상태 변경 작업입니다.
- 사용자가 Obsidian 편집기에서 입력한 내용은 **저장 후의 버전**을 일정 간격으로 복사합니다. Obsidian이 저장하기 *직전*의 모든 키 입력을 기록하는 버전 관리 시스템은 아닙니다. 필요하면 Obsidian의 파일 복구 기능/별도 백업도 함께 사용하세요.
- 명령 팔레트 → `원고 백업 목록 및 복원` 또는 AI 집필 화면의 `원고 백업·복원`을 엽니다. **복원 클릭 → 다시 누르면 복원** 확인 방식을 사용합니다. 복원 바로 전에 현 원고도 안전하게 백업합니다.
- 원고 하나에 남기는 백업 수를 제한하므로 오래된 백업은 삭제됩니다. 보관이 필요한 버전은 따로 보관하세요. 별도 Markdown 백업의 경우 보관함 용량이 증가합니다.

## 1.1에서 유지한 기능

- **Google Gemini 명시적 컨텍스트 캐싱:** 지원되는 Gemini 2.5/3 모델에서 `:countTokens` 후 `cachedContents.create`, 캐시 이름·만료시간 저장/재사용, 캐시 변경/만료시 갱신, 400·404 캐시 참조 오류 시 일반 요청으로 복구. Gemini 4 이후는 일반 요청과 자동 캐싱을 사용합니다.
- **고정/동적 자료 분리:** 작품개요·전체플롯·세계관·등장인물·집필규칙·장기기억·첫 5화의 **유효한** 요약은 고정 자료. 최근 회차 원고·5화 이후 유효 요약·현재 지시·작업별 대화는 동적 자료. 명시적 캐시를 만들 수 없는 모델에서는 일반 입력으로 전송.
- **회차 요약 유효성:** `05-기억/회차요약/`에 회차 요약 보관. 원본 수정 시 오래된 요약 자동 제외. 수동 3화씩 생성, 집필 전 자동 생성 옵션은 기본 OFF(최대 2화).
- **대화 슬라이딩 윈도우:** 동일 작업·회차의 최근 8턴(1~10 설정)만 원래 대화로 전송. 오래된 기록은 별도 AI 호출을 통해 누적 요약하고 `05-기억/대화기록.json`에 저장. 압축 실패 시 원본 유지.
- **API 4종:** Gemini, Anthropic Claude, OpenAI, HTTPS OpenAI 호환 API. API 키와 모델 ID는 개별 제공자에서 발급·확인해야 합니다.
- **기본 집필실:** 작품 생성, 회차 생성·상태·목표 글자 수, 설정집/플롯 열기, AI 초고·이어쓰기·퇴고·대사 개선·플롯·설정 검토, 사용량 토큰 기록.

## 개인정보·비용 및 실제 한계

- **API 키는 `.obsidian/plugins/novel-forge/data.json`에 평문 저장**됩니다. 다른 사람과 보관함 공유, 클라우드 동기화, Git 저장소 업로드 시 키 유출에 주의하세요. 외부 중계 서버를 운영하지 않으며 설정한 제공자의 API로 직접 전송합니다.
- **RAG 검색은 로컬**이지만 검색 결과의 텍스트와 기타 선택한 참고자료를 AI 요청 시 외부 제공자에게 전달합니다. `전송 내용 미리보기`에서 확인하고 필요하면 관련 옵션을 끄세요.
- Gemini 명시적 캐시는 입력 토큰 할인이 있을 수 있으나 캐시 **보관 비용이 별도로 발생**합니다. 모델·사용 빈도·TTL에 따라 전체 비용 절감 여부가 달라집니다. 항상 95% 할인 또는 수십 배 절약을 보장하지 않습니다. 지원 모델 정보: <https://ai.google.dev/gemini-api/docs/generate-content/caching>.
- 다단계 집필은 API 비용을 **늘릴 수 있습니다.** 사용량 화면은 실제 API가 반환한 입력/캐시 적중/출력 토큰을 기록하지만 실시간 화폐 비용과 저장 비용을 정확히 계산하지는 않습니다.
- AI가 제시하는 설정 검토와 출처 번호는 오류가 있을 수 있으며, 원문과의 **의미적 일치**를 자동 검증하는 기능은 아닙니다. 정설을 자동 승인하지 않습니다.
- 여러 PC의 보관함을 동시에 쓰면서 같은 원고를 수정할 경우에는 동기화 충돌이 발생할 수 있습니다. 백업은 장치별/보관함의 Vault 파일에 저장되며 실제 클라우드 백업을 대체하지 않습니다.
- 실제 Obsidian 앱 구동 및 유료 Gemini/Claude/OpenAI 키를 이용한 실통합 검증은 수행하지 않았습니다. **Node 모의 Obsidian Vault + API 응답 테스트와 문법 검사는 통과**했습니다.
